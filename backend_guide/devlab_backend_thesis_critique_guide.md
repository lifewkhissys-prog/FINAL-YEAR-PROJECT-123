# DevLab Backend Guides — Thesis Critique Module

The Thesis Critique Module allows lecturers to upload candidate thesis drafts (PDF/DOCX) and run automated, deep structure and writing diagnostics. It leverages FastAPI background tasks for asynchronous text extraction and the Groq API for LLM analysis.

---

## 1. Database Model (`app/models/thesis_critique.py`)

The thesis critique report is stored in the `thesis_critiques` table:

```python
class CritiqueStatus(str, enum.Enum):
    pending = "pending"
    processing = "processing"
    completed = "completed"
    failed = "failed"

class ThesisCritique(Base):
    __tablename__ = "thesis_critiques"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, index=True)
    lecturer_id: Mapped[int] = mapped_column(Integer, ForeignKey("users.id", ondelete="CASCADE"), nullable=False)
    candidate_name: Mapped[str] = mapped_column(String, nullable=False)
    programme: Mapped[str] = mapped_column(String, nullable=False)
    thesis_title: Mapped[str] = mapped_column(String, nullable=False)
    filename: Mapped[str] = mapped_column(String, nullable=False)
    status: Mapped[CritiqueStatus] = mapped_column(Enum(CritiqueStatus), default=CritiqueStatus.pending, nullable=False)
    report_json: Mapped[str | None] = mapped_column(Text, nullable=True)  # Stores the serialized LLM response
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now(), nullable=False)
```

---

## 2. API Endpoints

All endpoints are mounted under `/thesis-critique` and require the lecturer role (`require_lecturer`).

### Upload Thesis Draft
- **Route:** `POST /thesis-critique`
- **Request (Multipart Form):**
  - `candidateName`: String
  - `programme`: String
  - `thesisTitle`: String
  - `file`: UploadFile (PDF or DOCX)
- **Response:** `201 Created` with `ThesisCritiqueResponse` status="pending"

### List Reports
- **Route:** `GET /thesis-critique`
- **Response:** List of `ThesisCritiqueResponse` (excluding detailed `reportJson` for performance)

### Get Report Details
- **Route:** `GET /thesis-critique/:id`
- **Response:** `ThesisCritiqueResponse` (includes full parsed `reportJson` if completed)

### Delete Report
- **Route:** `DELETE /thesis-critique/:id`
- **Response:** `204 No Content`

---

## 3. Background Pipeline

1. **Upload:** Endpoint registers the draft metadata in the database with `status = "pending"` and schedules `process_thesis_critique_task` as a FastAPI `BackgroundTasks` job.
2. **Status Change:** The background task marks status as `"processing"`.
3. **Text Extraction:**
   - **PDF:** Extracted via `pdfplumber` page-by-page.
   - **DOCX:** Extracted via `python-docx` paragraph-by-page.
4. **LLM Diagnostics (Groq API):**
   - System prompt dictates formatting as JSON conforming to the requested diagnostics structure (overall score, category metrics, general critique paragraph, and detailed findings list).
   - Fallback mock report generator returns default structure if Groq is not configured or throws an API rate/network exception.
5. **Update:** Serializes LLM JSON, stores in `report_json`, sets status to `"completed"`, and commits transaction.

---

## 4. LLM JSON Structure

The output generated by Groq (or fallback) matches this JSON structure:

```json
{
  "summary": {
    "overall_score": 85,
    "metrics": {
      "academic_writing": 80,
      "methodological_rigor": 75,
      "literature_review": 90,
      "structure_coherence": 88
    },
    "general_critique": "Overall strong presentation of literature. Needs rigorous detail in methodology..."
  },
  "chapters": [
    {
      "name": "Chapter 1: Introduction",
      "score": 85,
      "findings": [
        {
          "category": "academic_writing",
          "original_text": "We wanted to look at how data gets sent...",
          "correction": "This research investigates the transmission of data...",
          "comment": "Avoid colloquial phrasing like 'wanted to look at'.",
          "severity": "medium"
        }
      ]
    }
  ]
}
```
